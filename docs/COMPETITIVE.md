# Fairy / Web 的竞争位置(v0.14)

一句话:**我们不是“又一个 DAST”,是“给 AI agent 用的、可审计的 web 执行层”。**

按检测覆盖、规则库、企业功能比,我们远不如商业 DAST,也不如 ZAP / Nuclei 成熟。
按授权边界、逐请求审计、证据链、审批门、MCP 原生、本地可控比,我们有明确差异点。

> 本文是能力面对比,不是同靶场实测。具体产品版本、许可、价格以官方为准。
> 唯一实测数字来自 `bench/`,只代表本机靶场,不能外推。

## 1. 先划清我们不是什么

- 不是 Burp / ZAP 的替代品:没有完整代理、手动重放、插件生态、模糊测试。
- 不是 Nuclei 的替代品:没有几千条模板、没有大规模并发扫描调度。
- 不是 exploit 框架:不做 getshell、横向执行、持久化、数据提取。
- 不是后渗透/横向框架:不偷凭据、不隧道、不隐蔽规避;权限矩阵只做只读可见性。
- 不是 SaaS:没有多租户、团队 RBAC、工单、合规报表、7x24 支持。

我们做的是:**在明确授权内,让 agent 真的发请求,并留下能复核的证据。**

## 3. 对商业 DAST

它们强在:

- 认证态深爬、宏/多步序列、SPA 抓取;
- 几千条检查、CVE 规则、WAF 绕过规则;
- 误报管理、合规报表、CI/CD、工单集成;
- 分布式扫描、调度、团队权限、支持。

我们强在:

- 先有 scope 才发请求,逐请求审计,越界是硬指标;
- 每条发现带 `request_id`,报告能独立复现;
- MCP 原生,模型可以直接调用;
- 审批门 + planner/worker,自主但不脱手;
- 本地零依赖,数据不出机器;
- WAF 行为画像 + 自适应只读检测;
- 多账号 × 多端点权限矩阵(BFLA/IDOR 候选,只读)。

**判断**:今天不能替代商业 DAST。能替代的是“手工记录 + 范围控制 + 证据整理 + 简单复现”这一段。
商业产品是“宽而重”,我们是“窄而可控”。

## 4. 对开源

### ZAP

ZAP 强在成熟、代理、手动测试、插件、模糊测试、社区。
我们强在状态机、账本、审批、证据链、Agent 接口。
**判断**:不替代 ZAP。理想关系是互补:ZAP 做手工/模糊,我们做授权执行、证据和 Agent 编排。

### Nuclei

Nuclei 强在模板生态、速度、CI、社区。
我们强在有状态规划、登录态差分、scope/审计、审批门。
**判断**:不替代 Nuclei。下一步可以“消费 Nuclei 模板”作为检查源,而不是重造模板库。

### Nikto / Wapiti / WhatWeb

单点工具,覆盖窄、噪声高。我们在流程和证据上更完整,但检查项不如它们专。
**判断**:可做补充,不做替代。

## 5. 对 AI 渗透代理

XBOW / PentestGPT / ARTEX 这类项目,强在自主规划、攻击链、公开基准/比赛成绩。
我们强在:

- 授权护照、逐请求审计、审批门;
- 账本 + 链 + planner/worker 状态机;
- 本地可控、零运行时依赖;
- 不把“候选”说成“已验证”。

差距:

- 没有它们的公开基准成绩;
- 自主性和攻击链深度还不如;
- 没有大规模真实目标数据。

**判断**:不自称超过。我们的差异是“安全可控的 agent 执行层”,不是“更强的自动攻击器”。

## 6. 真实差距(不回避)

1. 没有第三方同靶场实测,只有自己的 `bench/`。
2. 检测覆盖窄:SQLi/SSTI/头/CORS/跳转/暴露为主。
3. 认证深爬、角色矩阵、API schema/GraphQL 还不完整。
4. 没有模糊测试、没有利用验证,只判存在。
5. 报告/合规/UX/团队功能弱。
6. 没有 CI/CD、Jira、SIEM 集成。
7. WAF 分析只覆盖查询参数和四类编码。
8. 没有多租户、SaaS、RBAC、7x24 支持。
9. 社区和模板生态几乎为零。
10. 横向执行/后渗透明确不做——这是边界,不是待补的能力。

## 7. 唯一可信的数字

本机靶场 `npm run bench`:

```text
recall    100.0%
precision 100.0%
requests  46
findings  13
cost      3.5 请求 / 条
越界请求  0
```

这只能说明“已知类别没退化”,不是竞争力证明。
要和 ZAP/Nuclei 比,必须在同一靶场、同一 scope、同一 ground truth 下跑,统计:

- recall / precision;
- 每条 verified 发现的请求成本;
- 报告可复现率;
- 越界请求数;
- 人工复核时间。

## 8. 90 天

**30 天:可比**

- 同一本地靶场跑 Fairy / ZAP / Nuclei;
- 扩充 ground truth:API 越权、WAF、SPA;
- 公开 `bench/results` 和方法,不挑有利数据。

**60 天:补宽**

- 角色/权限矩阵、API schema/GraphQL、JWT/OAuth;
- 消费 Nuclei 模板作为检查源;
- CI 集成、SARIF/JSON 输出。

**90 天:真实目标**

- 3 个授权目标跑完整闭环;
- 统计每条 verified 发现的成本和可复现率;
- 出第一份可对外复现的对比报告。

## 9. 结论

今天的 Fairy / Web 不是“超过大厂”的产品,是:

> **一个授权优先、证据优先、Agent 原生的 web 执行层。**

它的价值不在“扫得比谁多”,而在“每一发都能解释、能回查、能停手”。
要超过大厂,先在同一张靶场上拿出可复现的数字,再谈覆盖和规模。
